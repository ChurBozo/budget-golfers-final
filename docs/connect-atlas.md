# Connecting the online database (MongoDB Atlas)

The API and website were built and tested against a local MongoDB. These steps move the data to MongoDB Atlas (free M0 cluster) and point the API at it. Nothing in the code changes: only `MONGODB_URI` in `api/.env`.

## 1. Create the cluster (about 5 minutes)

1. Sign in at https://cloud.mongodb.com and create a project called **Budget Golfers**.
2. **Create a cluster:** choose **M0 (Free)**. Sydney (`ap-southeast-2`) is the closest region to New Zealand. Name it `budget-golfers`.
3. **Database user:** Security > Database Access > Add New Database User. Choose password authentication, user name `bg_api`, and **Autogenerate Secure Password**. Copy the password somewhere safe. Role: **Read and write to any database**.
4. **Network access:** Security > Network Access > Add IP Address.
   - To develop: **Add Current IP Address**.
   - For Render later: **Allow access from anywhere** (`0.0.0.0/0`). Render's free plan has no fixed IP address; the database user's password protects the data.
5. **Connection string:** Database > Connect > Drivers > Node.js. It looks like
   `mongodb+srv://bg_api:<password>@budget-golfers.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=budget-golfers`.
   Put the database name **`budget_golfers`** after `.net/`:
   `mongodb+srv://bg_api:<password>@budget-golfers.xxxxx.mongodb.net/budget_golfers?retryWrites=true&w=majority&appName=budget-golfers`

If the password has symbols such as `@`, `:` or `/`, they must be URL-encoded (for example `@` becomes `%40`). The autogenerated passwords avoid this.

## 2. Load the data and run the API against Atlas

```bash
cd api
# in .env:
#   MONGODB_URI=mongodb+srv://bg_api:<password>@budget-golfers.xxxxx.mongodb.net/budget_golfers?retryWrites=true&w=majority
#   JWT_SECRET=<a long random string>
npm run seed          # loads the 4 collections into Atlas and builds every index
npm start             # "MongoDB connected: mongodb+srv://***@budget-golfers..." then port 3000
```

Check it with `http://localhost:3000/api/health`, or run `npm run postman` (the full Postman collection). In Atlas, Database > Browse Collections now shows `users`, `courses`, `rounds` and `clubs`.

Then start the website (`cd web && npm run dev`); nothing changes there, because it still talks to the API on port 3000.

## 3. Database evidence for the report

Run the same checks against Atlas with mongosh (or the shell built into MongoDB Compass):

```bash
mongosh "mongodb+srv://budget-golfers.xxxxx.mongodb.net/budget_golfers" --username bg_api api/seed/check-database.mongosh.js
```

Screenshots of Atlas's **Browse Collections** and **Indexes** tabs are also good evidence of a working online database.

## 4. Later: put the API and website online

- **API on Render:** a new Web Service from the GitHub repository, root directory `api`, build `npm install`, start `npm start`. Environment variables: `MONGODB_URI` (as above), `JWT_SECRET`, `NODE_ENV=production`, and `CORS_ORIGINS` (the Vercel address).
- **Website on Vercel:** root directory `web`, environment variable `VITE_API_URL` (the Render address).
- **Phone app:** set `API_BASE_URL` in `app/config/mapbox.json` to the Render address (https), or change it in the app under Settings > Account > Server.

Never commit `.env` or the connection string: both are git-ignored.
